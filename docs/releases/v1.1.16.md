# Space Data Network v1.1.16

Space Data Network 1.1.16 is the node as on `main` at the tag `v1.1.16`, shipping alongside `@spacedatanetwork/sdn-js@4.1.0`. It replaces v1.1.15 as the release to download.

## Followed lanes, publications, and flow reliability

- **Followed lanes keep their current batch across restarts (#265 / #1099).** On a node that subscribes to a lane and also holds an older publication of it, the retention pass at start now leaves subscribed `replace-current` lanes to their subscription (while keeping `archive-all` publication pinning active). `sync subscriptions` computes lag from the store at query time, producers attribute carried-over records to the lane's producer rather than an earlier peer's bytes, and a batch that grows while it is listed refreshes its statement and continues instead of raising `follow_refused`.
- **Mixed-version publication manifest verification (#266 / #1083).** `VerifyDatasetPublicationManifest` now uses the manifest's stated `IndexSchemaHash` when verifying Ed25519 signatures, so nodes on different `PublicationState.fbs` builds verify each other's manifests while tampering still fails verification.
- **Retracted lanes drop interrupted publication marks cleanly (#267 / #1085).** Interrupted publication resume skips retracted lanes with one log line and zero retries or alerts, and `RunPublicationRetract` clears pending marks; update helper stop grace for running publications is covered end to end.
- **Stream reset cancels producer `read-chunk` reads (#269 / #1093).** The remote-records relay and `sdn-js` libp2p sync keep the write side of `read-chunk` streams open while reading so stream resets cancel producer engine reads immediately instead of running to timeout.
- **Per-attempt flow ledger stamps (#268 / #1018).** Sibling timers of one flow service bind their outcome callback to their own attempt stamp, so a clean run of one timer no longer erases a real failure of the other timer.
- **Interrupted service flows discard torn WASM instances (#273 / #1084).** `ServiceFlow.FireTrigger` now discards its WASM instance whenever a run is cancelled, errors, or panics, preventing a subsequent manual run from returning an empty `"ok"` drain in milliseconds without fetching.
- **Short FlatBuffer body guard (#264 / #944).** All `*BufferHasIdentifier` checks guard `len(body) >= 8` first so short bodies (such as `POST {}`) return HTTP 400 cleanly instead of panicking.
- **Full CPU feature-flag AOT cache keys (#270 / #815).** `aotCPUProfile()` includes a SHA-256 digest of the host CPU's feature flags alongside the microarchitecture level so CPUs sharing `x86-64-v4` with different optional extensions never share an AOT cache.
- **Synchronous admin bind & non-ephemeral E2E ports (#272 / #1097).** The daemon binds its admin TCP listener synchronously before serving (failing immediately on port conflict instead of running headless), and real-daemon E2E tests pick non-ephemeral loopback ports (`20000–29999`) with exit-aware readiness polling.
- **Windows published-installer smoke cleanup (#271 / #1056).** Retries temp-directory cleanup on Windows (`maxRetries`/`retryDelay`) and warns on transient `EPERM`/`EBUSY` instead of failing a passing release smoke.

## Standards catalog and `@spacedatanetwork/sdn-js@4.1.0`

- **Persisted node identity (`@spacedatanetwork/sdn-js@4.1.0`, #275 / #113).** Adds browser-safe `loadOrCreateIdentity(store)` and Node-only `fileIdentityStore(path)` (`@spacedatanetwork/sdn-js/node`, mode `0700`/`0600` or Windows owner-only ACL, atomic temp-file rename, integrity-checked envelope, refuses to replace corrupted files) so Node users keep a stable libp2p PeerID across restarts.
- **Internal engine frame filtering & browser storage cleanup (#274 / #724).** Excludes FlatSQL internal frame types (`FCK`, `FMB`, `FSG`) from `GET /api/v1/standards`, purges retired `:record-envelopes` keys on store open, removes the unused `desktopPersistenceBaseUrl` client, and provisions Go + patched static WasmEdge in `npm-publish-sdn-js.yml`.

## Installer and key-password notes

**Linux: a fresh node gets its key password file automatically.** Where `/sys/class/dmi/id/product_uuid` is root-only and no `SDN_KEY_PASSWORD` / `SDN_KEY_PASSWORD_FILE` is configured, installers generate a 0400 random password file on fresh installs (`~/sdn-key-password` for `install.sh`, `/var/lib/spacedatanetwork/key-password` with systemd drop-in for `.deb`/`.rpm`, `/app/data/key-password` for container uid 1000). The credential store follows the identity's key password order, and CLI config discovery ignores daemons owned by unrelated local accounts.

**Rollback.** No on-disk store format change: v1.1.15 nodes interoperate with v1.1.16 nodes as before.
