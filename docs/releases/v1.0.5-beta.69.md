# Space Data Network v1.0.5-beta.69

This build is about the parts of a release that had been quietly wrong. The
node now reports the version it actually is, its IPFS half identifies as an SDN
node on Kademlia, the Windows bundle is genuinely self-contained and installs
cleanly, and the write path is several times faster. Install with the one-liners
at https://spacedatanetwork.org, open the desktop app, or run the container;
docs/INSTALL.md is the operator path.

## What changed

- **A binary reports its own build.** `spacedatanetwork version` answered a bare
  `1.0.5` in every release before this one: the release tag was stamped by the
  Dockerfile and both local release scripts, but not by the job that builds the
  published archives. A node, a support conversation and an update check now all
  see `1.0.5-beta.69`, and peers see it too — the libp2p agent string was a
  compile-time constant no link-time stamp could reach.

- **The IPFS side identifies as SDN.** Peers decide membership from the identify
  agent-version, and a node runs two libp2p hosts: its own and a Kubo. The Kubo
  announced a bare `kubo/<version>`, so on Kademlia the IPFS half of every SDN
  node was indistinguishable from any other IPFS node. Both the node-managed and
  operator-run cases now carry the SDN name, through Kubo's own
  `Version.AgentSuffix` config key — no patched binary.

- **Windows is a single self-contained binary, and installs.** It had been
  importing `libstdc++-6.dll`, `libxml2-16.dll` and `zlib1.dll` — files that
  exist only where MSYS2 is installed — and the guard that was supposed to catch
  that named the libraries to reject rather than asking which imports Windows
  ships. The installer also failed at its last step on every Windows machine:
  PowerShell turns a native command's stderr into a terminating error, so a
  completely successful install reported failure after everything was on disk.

- **Faster, durable writes.** A write window now costs one fsync instead of two
  and a few multi-row statements instead of ~460, and the control database runs
  WAL at `synchronous=NORMAL`. Measured 2.55x on the store write path. NORMAL
  gives up the last commits before an OS crash or power cut — bounded in bytes,
  not in time — which is the trade a replicated network can make and a
  single-node deployment holding unique records should not.

- **Two silent record-loss bugs, both fixed.** A `$CAT` supersede key containing
  a NUL was truncated when read back, so every object in one catalog collapsed
  to a single key and a second producer kept one row out of two. And the pending
  dataset-announcement lane deleted other writers' in-flight files, losing
  12–46% of concurrent announcements with the error swallowed at debug level.

- **Provenance you can act on.** Supersede is now scoped to (producer, source),
  so one provider ingesting the same catalog in two formats keeps both lanes'
  provenance instead of the second silently deleting the first.

## Known gaps

- Artifacts are not code-signed. macOS and Windows will warn on the desktop
  installers; the `curl | bash` and `irm | iex` paths are unaffected. Checksums
  are published and verified by the installers.
- The `helia`/`libp2p` layering in the browser client spans two major versions
  and carries an unpatched advisory with no in-range fix.
