# Space Data Network v1.0.5-beta.1

The node's record store is now the FlatSQL control database itself: records
stream straight into it as they arrive and a restart opens the file on disk.
Nothing is replayed or re-ingested at boot. This build also ships the first
desktop app that runs the bundled node, a Docker image that boots ready with a
native (AOT) engine, and Windows and Linux arm64 bundles beside the macOS and
Linux x86-64 ones. Install with the one-liners at https://spacedatanetwork.org,
open the desktop app, or run the container; docs/INSTALL.md is the operator
path.

## What changed

- **Records stream into FlatSQL.** The producer row holds the record bytes;
  the record-catalog journal, the `flatsql-streams/` directory and the boot
  replay are gone. A node that restarts serves what is on disk immediately.
  Catalog ($CAT) rows supersede on ingest. `spacedatanetwork store-wipe
  --config <file>` empties a store in place with an explicit preserve list
  (identity, auth, peers, flows) for the cutover; there is no migration from
  earlier layouts.
- **Engine record state is one unit.** The engine's arena and its partition
  map are checked against each other before the store opens and discarded
  together when they disagree, so a rebuilt store never routes rows to the
  wrong source. A cold rebuild seats no record twice.
- **Dataset publications verify by the key they name.** A publication signed
  with the provider's Ed25519 signing key is accepted when the provider is
  known by a Secp256k1 peer identity; the consumer tries every key the
  provider is known by and lets the signature choose.
- **Search schemas** regenerated for Space Data Standards 1.217.0.
- **Docker image** (`dockerdigitalarsenal/space-data-network`): the AOT
  engine is prewarmed at build time, the wallet sign-in assets are served
  same-origin, and `/app/data` is the one volume (store, keys, auth, peers).
- **Desktop app** (macOS Apple Silicon and Intel, Windows x86-64, Linux
  x86-64): starts the bundled node on launch, shows the node's own dashboard,
  and reveals the recovery phrase on request from its menu.
- **Operational alerts.** `GET /health` reports `degraded` with alert counts
  when a retrieval lane keeps failing, a dataset publication is rejected, a
  flow is denied a capability, the engine is poisoned or rebuilding, or an
  update fails; `GET /api/v1/status/alerts` (operator session) lists them,
  `/metrics` carries `sdn_alerts_active`, and every transition logs one
  `OPS ALERT` line.
- **Bundles** for Windows x86-64 (zip) and Linux arm64 join macOS Apple
  Silicon and Linux x86-64.

## Standards

Built against Space Data Standards 1.217.0; FlatSQL 1.4.5 on WasmEdge 0.16.4.

## Upgrading

The store layout changed. Fleet nodes on the update feed take this build
through `spacedatanetwork update install`; an existing store must be wiped
(`store-wipe`) or started fresh. Identity, auth and peer state are preserved by
the wipe.

## Known limits in this beta

- CelesTrak lanes honour the upstream politeness window (one request per file
  per three hours per address); a node that restarts mid-fetch waits for the
  lane's own backoff before it fetches again.
- A restart pays a warm reconcile of the engine's hot window (seconds to about
  a minute on a full catalog node).
- The update feed serves linux/amd64 on the beta channel; other platforms
  update by reinstalling, the desktop app by downloading the next build.
- One update-signing root; rotation lands in a later beta.
