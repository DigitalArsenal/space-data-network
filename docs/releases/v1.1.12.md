# Space Data Network v1.1.12

Space Data Network 1.1.12 is the node as on `main` at the tag `v1.1.12`. It replaces v1.1.11 as the release to download.

## A publication stays available while the node's IPFS repository holds it

A node that imports a lane's publications also lists them (`list-published`) and serves their files (`read-shard`, `read-index`). A follower's lane retention removes the files of the batches it no longer keeps as current, but it keeps their listing rows for 24 hours. Until this release those rows were listed `unavailable (shard_missing)` even when the node's IPFS repository still held the content and served it over Bitswap. On 2026-11-21 host-01 listed four of host-02's five CelesTrak GP batches that way. Readers that drop unavailable rows, such as the SpaceAware console, then had no earlier batch to fall back to.

Now a shard or index whose file is gone counts as present when the repository holds all of its content. Every block of its DAG must be local, and the node fetches nothing to check this. A shard must also be the published size. Such a row:

- lists as `available`;
- is served by `read-shard`, `read-index` and `read-shard-batch`, with the bytes read from the repository;
- is not retired while it stays so.

`docs/SUBSCRIPTIONS.md` has the details.

## Compatibility

- **Rollback to 1.1.11:** nothing is stored differently, so a rollback just lists rows from their files again.
- **Publications:** a node on a build older than 1.1.6 does not accept publications signed by 1.1.6 or later, 1.1.12 included.
- **Stores:** unchanged from 1.1.10 (store format 5, layout 2).

## Security: install 1.1.4 or later

Every release up to and including 1.1.0, and the container images tagged `1.1.1` and `v1.1.1`, trust one update-signing key, `d4a971a7e534`, and that key is compromised. 1.1.4 through 1.1.12 trust only the update key `12cb25de07c0` and refuse the old one wherever it appears. The v1.1.4 release notes say what to do on a node that cannot be replaced.

**Downloads.** Installers and archives for macOS, Linux and Windows, the container image `dockerdigitalarsenal/space-data-network:v1.1.12` (linux/amd64 and linux/arm64), the signed update feed and their checksums are attached to this release. Every platform is built from the tagged commit.

## Updating an installed node

- **From 1.1.4 through 1.1.11,** run `spacedatanetwork update install`, or let the node take the release from its channel within its rollout window. The release channel at `https://sdn.spaceaware.io/updates` serves this release. The node keeps its identity and its data, and the replaced build is kept as a rollback slot. Desktop, package, VM-bundle and container installs do not update themselves: install the new release.
- **From 1.1.4 through 1.1.9,** read the v1.1.10 notes first: the first start of 1.1.10 or later converts the import settings into subscriptions.
- **From 1.1.0 or earlier,** update by hand: stop the node, install the 1.1.12 download or package in place of the old binary (keep `keys/` and the config), and start the node.
