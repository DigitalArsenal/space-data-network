Become a Data Provider

Publish your space data to an open, decentralized network in four steps. No gatekeepers, no contracts — just a node, a signed identity, and a standard schema.

1 · Identity 2 · Schema 3 · Publish 4 · Verify
1 Run an identity node

Your identity is a crypto wallet, not an account

Start by installing and initializing a node. The one-line installer puts a self-contained CLI in your user directory — no admin rights required:

macOS / Linux
curl -fsSL https://spacedatanetwork.org/install.sh | bash
Windows PowerShell
irm https://spacedatanetwork.org/install.ps1 | iex
Terminal
spacedatanetwork init     # creates your wallet + node identity
spacedatanetwork start    # run as a background service
spacedatanetwork status   # confirm it is up

That init did something important: it generated a cryptographic wallet — a recovery phrase (BIP-39 mnemonic), the same technology that secures Bitcoin and Ethereum wallets, encrypted on your disk. From that one phrase the node derives everything it needs: your network address (PeerID), an Ed25519 signing key, and an X25519 encryption key. There is no signup, no password, and no company holding your account. Whoever holds the phrase holds the identity, so back it up like you would a wallet.

Why this matters, in plain terms: the Space Data Network has no central authority to vouch for anyone. Instead, every record you publish is automatically stamped with your signature. Anyone, anywhere, can check the math and know two things for certain: the data really came from you, and nobody altered it in transit. Your identity is your reputation — and it is portable, provable, and yours alone.

Next, fill in your public profile (an Entity Profile Message, or EPM) so the network knows who is behind the node — only public fields, never key material:

Terminal
# interactive wizard for your public org profile
spacedatanetwork identity wizard

# export it as a signed vCard or QR code
spacedatanetwork identity export --format text
spacedatanetwork identity export --format qrcode

Why be discoverable? Your node broadcasts your signed profile to the network, which means:

  • Customers find you — one search (search providers) surfaces your organization to everyone looking for your kind of data. No marketing pipeline, no integration contract.
  • Everything you publish is attributable — reputation accrues to your identity with every verified record.
  • Trust travels with the card — your exported vCard works in any contacts app, but also carries your signed identity. Scan the QR at a conference and the other party imports a profile they can verify mathematically, keys included.
Example signed vCard
BEGIN:VCARD
VERSION:4.0
FN:Dr. Jane Smith
ORG:Example Space Agency
TITLE:Chief Scientist
EMAIL:jane@example-agency.org
X-SDN-PEER-ID:12D3KooWQmVzEx4mp1eNodePeerId7QhcVTKtGkbq
X-SDN-EPM-CID:bafybeigdyrzt5sfp7udm7hu76uh7y26nf3e...
X-SDN-EPM-SIGNATURE:<Ed25519 signature>
X-SDN-EPM-SIGNATURE-TIMESTAMP:2026-07-02T12:00:00Z
X-SDN-DIRECTORY-KIND:organization
X-SDN-EPM-B64:<complete signed EPM bytes>
END:VCARD

Scan to import a
verifiable identity

The ordinary contact fields are for humans; the X-SDN-* extensions are for machines. X-SDN-EPM-B64 carries the complete signed identity record — importers verify its signature and trust it over anything a person could edit by hand.

Prefer a GUI? The desktop app bundles a full node with a wallet dashboard that walks you through the same steps. Docker images and native Linux packages are on the downloads page.
2 Pick a schema

All data on the network is Space Data Standards

Only Space Data Standards (SDS) FlatBuffer data is allowed on the network — that is what makes every record parseable and verifiable by every participant. Match your data to one of the 160+ registered schemas:

Your dataSchema
TLEs / orbital elementsOMM
EphemeridesOEM
Conjunction warningsCDM
Maneuver plansMPE
Object catalogsCAT
Tracking / sensor dataTDM, EOO
  • The JavaScript and Go SDKs include converters for common formats (TLE, CCSDS XML/KVN) to SDS FlatBuffers.
  • Browse everything registered on a live node: GET /api/v1/catalog.
  • Nothing fits? Propose a new schema — SDS FlatBuffers evolve without breaking existing parsers.
3 Publish

Push data through the SDK or REST API

Any process can become a publishing peer with the JavaScript SDK:

JavaScript / TypeScript
import { SDNNode } from '@spacedatanetwork/sdn-js';

const node = new SDNNode();
await node.start();

// publish a record under its SDS schema code
await node.publish('OMM', ommData);

Or post validated FlatBuffer records to your local daemon's REST API. The publish endpoint requires an authenticated session at Standard trust or higher — there is no localhost bypass. Log in once with your HD wallet at http://127.0.0.1:5001/login (the first account to authenticate on a fresh node is bootstrapped as Admin), then use the session token from the sdn_wallet_session cookie:

REST
# session token = the sdn_wallet_session cookie value from /login
export SDN_SESSION_TOKEN='<your-session-token>'

curl -X POST http://127.0.0.1:5001/api/v1/data/publish/OMM \
  -H "Content-Type: application/octet-stream" \
  -H "Accept: application/json" \
  --cookie "sdn_wallet_session=${SDN_SESSION_TOKEN}" \
  --data-binary @omm.fbs

The session is delivered only as that cookie (bearer headers are not accepted). Automated pipelines can mint one programmatically: POST /api/auth/challenge, Ed25519-sign the challenge with your wallet signing key, then POST /api/auth/verify and capture the Set-Cookie value. CLI commands accept the same token via --session-token or the SDN_SESSION_TOKEN environment variable.

Under the hood, every record is validated against its schema, content-addressed (CID), appended to your node's hash-chained publication log, Ed25519-signed, and announced to subscribers over GossipSub. Consumers can cryptographically verify that the data came from you and was never altered.

4 Verify

Confirm your data is live and discoverable

Terminal
# find yourself as a provider
spacedatanetwork search providers "Example Provider" --schema OMM

# inspect published data
spacedatanetwork search data --schema OMM --format json

Useful REST checks on your node: /api/v1/stats (peers and record counts), /api/v1/log/{schema} (your publication log), and /api/v1/data/records/{schema}/{cid} (fetch any record by CID).

Optional · Sell on the marketplace

Publish a signed marketplace listing

Commercial data products and algorithms are sold as encrypted WASM modules. The network keeps exactly one canonical, signed PLG listing per PLUGIN_ID + VERSION; buyers get per-customer key delivery and decrypt locally. Selling is a three-step flow:

1. Package and encrypt your module. Build it with the Module SDK, then encrypt the artifacts and generate a catalog.json:

Terminal
# validate + encrypt a single module artifact
npx space-data-module check --manifest ./manifest.json --wasm ./dist/isomorphic/module.wasm
npx space-data-module protect --manifest ./manifest.json --wasm ./dist/isomorphic/module.wasm

# or encrypt a whole plugin tree and emit catalog.json
npm run seed:orbpro-module-catalog -- --plugin-root ./my-plugins

2. Publish the signed catalog to your provider node. The request is Ed25519-signed with your admin HD wallet; the provider node only accepts admin-signed publishes:

Terminal
spacedatanetwork plugins publish-orbpro \
  --plugin-root ./my-plugins \
  --wallet-env ./wallet.env \
  --wallet-wasm ./hd-wallet-wasi.wasm \
  --target /dns4/<host>/tcp/<port>/wss/p2p/<peer-id>

For a single plugin over HTTP instead, POST /api/v1/plugins/upload (multipart: the bundle, metadata JSON with id and version, and signature_hex — your Ed25519 signature over the bundle's SHA-256), using the same session cookie as publishing.

3. Verify your listing is live. The node materializes one PLG listing per published module:

Terminal
curl http://127.0.0.1:5001/api/module-delivery/listings

spacedatanetwork marketplace list
spacedatanetwork marketplace show <listing-id>
The marketplace CLI is discovery-only (list, search, show) — listings are created by plugins publish-orbpro or the upload endpoint, never by hand.
